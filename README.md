## Импорт табличных данных

Реализованы CSV, XLSX, SQLite и Parquet: предварительное сканирование и чтение порциями.
ImportSession управляет импортом для всех источников: пауза и продолжение,
преобразование типов, прогресс и получение итогового DataFrame.

## Запуск

Выполняйте команды из папки `StatSoft_Testing`:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Нужен Python 3.10 или новее. Тесты используют стандартный модуль unittest.

## Управление импортом

```python
from table_import import CsvSource, ImportSession

source = CsvSource("sales.csv", delimiter=";")
sheet = source.list_sheets()[0]
metadata = source.scan(sheet=sheet, sample_rows=100)

with ImportSession(
    source, sheet=sheet, chunk_size=1000,
    dtype={"id": "Int64", "amount": "Float64"},
    metadata=metadata,
) as session:
    for chunk in session:
        print(session.progress)
        session.pause()
        break

    # Другую работу можно выполнить здесь. Сессия остаётся открытой.
    session.resume()
    result = session.run()  # Дочитать и получить единый DataFrame.
    print(session.progress)
    print(result)
```

Словарь dtype должен ссылаться на существующие столбцы. Для непрерывного
импорта достаточно `result = session.run()`. Для ручного чтения можно вызывать
`next(session)` или итерироваться циклом `for`. По окончании цикла итог
доступен через `session.result()`; повторный вызов не читает источник заново.

Рабочая демонстрация с временным CSV: `python import_example.py`.

### Состояния и ресурсы

- `ready`: сессия создана, источник ещё не открыт.
- `running`: идёт последовательное чтение порций.
- `paused`: `pause()` остановил выдачу порций; `resume()` разрешает продолжение.
  Итерация paused-сессии завершается без чтения, `run()` требует сначала resume().
- `completed`: источник исчерпан, DataFrame собран. Конец определяется следующей
  попыткой чтения после последней порции, а не её размером. `for` и `run()`
  делают эту попытку автоматически.
- `failed`: чтение или преобразование завершилось ошибкой. Читатель закрывается,
  накопленные порции освобождаются. Продолжение этой сессии запрещено, чтобы
  ошибочная порция не была пропущена. После исправления данных нужна новая сессия.
- `closed`: незавершённый импорт окончательно закрыт через close() или выход
  из with. Продолжить его нельзя. Готовый результат completed-сессии сохраняется.

`pause()` сохраняет открытый читатель, `close()` освобождает его. Пауза действует
только внутри одного процесса; выхода из with и перезапуска она не переживает.
Работа синхронная: управление выполняется между порциями, без фоновых потоков.

### Преобразование типов

Каждая порция преобразуется до включения в результат. Поддерживаются строковые
обозначения типов:

| dtype | Правило |
| --- | --- |
| Int64 | Целые с пропусками; дроби и выход за диапазон int64 — ошибка |
| int64 | Целые без пропусков; NULL также вызывает ошибку |
| Float64 | Числа с поддержкой pd.NA |
| float64 | Числа с плавающей точкой; пропуски представлены NaN |
| string | Строки с сохранением признака пропуска |
| boolean | true/false, 1/0 (строки без учёта регистра), логические значения и пропуски |
| datetime64[ns] | Даты, строки ISO 8601 и пропуски; без часового пояса |

Политика ошибок строгая: значения не заменяются на пропуски для сокрытия ошибки,
дробные числа не обрезаются до целых. TypeConversionError содержит источник,
лист, столбец, целевой тип, причину и, когда определено, номер проблемной строки
и значение. Номер относится к строкам данных с 1, а не к физической строке файла.
Для SQL это позиция в результате запроса. Ошибка в порции не увеличивает прогресс.

Для столбцов без явно заданного dtype итог нормализуется через convert_dtypes()
после объединения всех порций. Явная схема сохраняется и в итоговом DataFrame.
Преобразование работает со значениями, уже прочитанными источником: оно не
восстанавливает исходное текстовое представление вроде ведущих нулей CSV,
если парсер ранее превратил его в число. Для смешанных исходных данных без
явной схемы полная независимость типов и значений от chunk_size не гарантируется.

### Прогресс и результат

`session.progress` — неизменяемый снимок ImportProgress:

- status — состояние сессии;
- rows_imported — число успешно принятых строк;
- chunks_imported — число успешно принятых непустых порций;
- total_rows — ожидаемое число из metadata, либо None;
- total_rows_is_estimate — является ли число приблизительным;
- fraction — rows_imported / total_rows, либо None для неизвестного/нулевого
  общего числа и при превышении ожидаемого числа;
- total_rows_exceeded — принято больше строк, чем указано в metadata.

Полный подсчёт строк ради процентов не выполняется. Даже для пустой таблицы
после завершения fraction=1.0, rows_imported=0 и chunks_imported=0.

Передайте `metadata=source.scan(sheet=sheet, sample_rows=100)` в ImportSession
для процента. Без metadata сохраняется прежнее поведение: до завершения
известно только число принятых строк и порций. Автоматическое сканирование
при создании сессии не выполняется.

Для CSV процент обычно приблизительный; обозначайте его словом «около».
Для Parquet число строк точное. Если total_rows_exceeded=True, показывайте
«ожидаемое число строк превышено», не 140% и не искусственные 99%.
При равенстве принятых и ожидаемых строк fraction может быть 1.0, но это
НЕ признак завершения: только status="completed" подтверждает конец чтения
и готовность DataFrame. На паузе и при ошибке процент не растёт сам по себе.

После завершения total_rows заменяется фактическим числом, fraction=1.0,
total_rows_is_estimate=False, total_rows_exceeded=False. Даже заниженная
оценка не ограничивает чтение. У завышенной оценки процент в конце поднимется
до 100% после подтверждения конца источника.

Имя листа metadata должно совпадать с sheet; row_count — неотрицательное целое
или None. Метаданные должны относиться к тому же источнику, который не менялся
после scan. Проверка имени листа не доказывает идентичность файла: автоматического
контроля версии или содержимого источника нет. При превышении устаревшего
«точного» размера действует то же правило: процент неизвестен, чтение продолжается.

`result()` до завершения вызывает ImportStateError. Метод возвращает копию
готового DataFrame; изменение выданной порции также не меняет сохранённые данные.
Порции хранятся в памяти и объединяются один раз. На объединение и копии нужна
дополнительная память; результат должен помещаться в RAM.

## Общий интерфейс и добавление источников

TableSource в table_import/source.py описывает контракт через Protocol:

```python
source.list_sheets()
source.scan(sheet=sheet, sample_rows=100)
source.iter_chunks(sheet=sheet, chunk_size=1000)
```

При использовании именованных аргументов эти вызовы одинаковы для CSV, XLSX
и SQLite, а также Parquet. Старые вызовы без sheet у CSV и SQLite сохранены для совместимости.
Для CSV имя листа — имя файла без расширения; для SQLite по умолчанию это
имя выбранной таблицы или "query" для запроса (можно задать sheet_name).

Чтобы добавить формат, реализуйте эти методы. iter_chunks должен возвращать
закрываемый генератор DataFrame с неизменным набором уникальных столбцов; для
пустой таблицы выдайте один пустой DataFrame со схемой. Освобождайте ресурсы
в finally или with. Наследование от TableSource не обязательно. ImportSession
не содержит проверок на CsvSource, XlsxSource или SqlSource и не требует правки
при добавлении источника, соблюдающего контракт.

## Чтение CSV без сессии

```python
from contextlib import closing
import pandas as pd
from table_import import CsvSource

source = CsvSource("sales.csv", delimiter=";", encoding="utf-8")
metadata = source.scan(sample_rows=3)
print(metadata)

with closing(source.iter_chunks(chunk_size=4)) as chunks:
    result = pd.concat(list(chunks), ignore_index=True)
print(result)
```

`closing` закрывает генератор и открытый файл даже при досрочном выходе
из блока. При полном чтении файл закрывается автоматически.

## XLSX

```python
from contextlib import closing
import pandas as pd
from table_import import XlsxSource

source = XlsxSource("sales.xlsx")
print(source.list_sheets())
metadata = source.scan(sheet="Продажи", sample_rows=100)
print(metadata)
with closing(source.iter_chunks(sheet="Продажи", chunk_size=1000)) as chunks:
    result = pd.concat(list(chunks), ignore_index=True)
```

- Используется openpyxl в режиме read_only. Книга и файл закрываются при
  завершении чтения, ошибке или явном закрытии генератора.
- Первая строка — непустые уникальные заголовки, приводимые к строкам.
  Пустые ячейки справа от заголовка отбрасываются. Данные вне ширины
  заголовка вызывают SourceReadError с номером строки.
- Лист без строк даёт один пустой DataFrame без столбцов. Лист только с
  заголовком даёт один пустой DataFrame с этими столбцами. Пустая первая
  строка в непустом листе считается ошибкой формата.
- Пустые строки между данными сохраняются как строки пропусков.
  Текстовые маркеры вроде NA остаются текстом, в отличие от правил CSV.
- Формулы не вычисляются: data_only=True читает сохранённые результаты.
  Если сохранённого результата нет, значение будет пропуском.
- Сканирование получает одну порцию не более sample_rows строк и закрывает
  генератор. Число строк всей таблицы остаётся неизвестным (row_count=None).
- Потоковое чтение листа не исключает затрат на открытие книги и её общие
  структуры. Постоянное время открытия XLSX любого размера не гарантируется.
- Типы определяются отдельно для выборки и каждой порции.
- Выбор отсутствующего листа вызывает SourceReadError со списком доступных.

## Parquet

```python
from table_import import ParquetSource, ImportSession

source = ParquetSource("sales.parquet")
sheet = source.list_sheets()[0]
metadata = source.scan(sheet=sheet, sample_rows=100)
print("Всего строк:", metadata.row_count)
with ImportSession(source, sheet=sheet, chunk_size=1000) as session:
    result = session.run()
```

Демонстрация создаёт настоящий временный Parquet: `python parquet_example.py`.
Для записи собственного файла: `df.to_parquet("sales.parquet", engine="pyarrow", index=False)`.
Простое переименование CSV не создаёт Parquet.

- Используется pyarrow (Apache-2.0). Поддерживается один локальный файл,
  имя листа — имя файла без расширения. Каталоги partitioned datasets,
  удалённые хранилища и зашифрованные файлы не входят в эту реализацию.
- Число строк берётся из footer-метаданных без полного чтения данных.
  Типы pandas получаются при преобразовании Arrow-схемы и выборки;
  пропуски считаются только по выборке, включая NaN.
- iter_batches выдаёт не более chunk_size строк за раз; размер порции
  не обязан совпадать с размером row group. Группы строк не являются листами.
- Для сканирования читается первая порция не более sample_rows строк.
  Чтение и декодирование страниц Parquet может затронуть больше данных,
  чем число возвращённых строк. Размер footer растёт с числом столбцов
  и групп строк, поэтому абсолютно постоянное время не гарантируется.
- Целые с NULL преобразуются в nullable-типы pandas без промежуточного float;
  строки вроде "001" сохраняются строками, если такова схема файла.
- Вложенные list, struct и map отклоняются с SourceReadError и именем столбца.
  Автоматического разворачивания вложенных значений нет.
- Пустой файл Parquet со схемой даёт один пустой DataFrame с типами столбцов.
  Физически сохранённый индекс pandas читается как обычный столбец;
  итоговая сессия создаёт новый RangeIndex.
- Пауза, dtype и итоговый DataFrame работают через общий контракт. Передача
  metadata от scan в ImportSession включает точный прогресс по строкам.
- Полный результат и промежуточные порции должны помещаться в оперативную память.

## SQLite

Используется стандартный модуль Python sqlite3; дополнительная зависимость
не нужна. SqlSource поддерживает только SQLite, несмотря на общее имя класса.

```python
from contextlib import closing
import pandas as pd
from table_import import SqlSource

source = SqlSource("sales.db", table="sales")
print(source.list_sheets())  # ["sales"]
print(source.scan(sample_rows=100))
with closing(source.iter_chunks(chunk_size=1000)) as chunks:
    result = pd.concat(list(chunks), ignore_index=True)
```

Результат SELECT также является одним логическим листом, даже при JOIN:

```python
source = SqlSource(
    "sales.db",
    query="""
        SELECT o.id, c.name AS customer_name, o.amount
        FROM orders AS o
        JOIN customers AS c ON c.id = o.customer_id
        WHERE o.amount >= ?
        ORDER BY o.id
    """,
    params=(1000,),
    sheet_name="Заказы",
)
metadata = source.scan(sheet="Заказы", sample_rows=100)
with ImportSession(source, sheet="Заказы", chunk_size=1000) as session:
    result = session.run()
```

Пример предполагает существующие таблицы orders и customers. Для именованных
параметров используйте `:minimum` в SQL и `params={"minimum": 1000}`.
Указывать table и query одновременно нельзя; старый вариант table сохранён.
Параметры передаются SQLite отдельно от SQL, без подстановки строк.

Готовая демонстрация сама создаёт временную базу с данными и удаляет её после
завершения: `python sqlite_example.py`.

- Один логический лист — результат одного SELECT. Поддерживаются JOIN, CTE,
  параметры, чтение представлений через query. table — сокращение для SELECT *.
  Поддерживается существующая файловая SQLite-база, не другие SQL-системы.
- Несколько SQL-операторов в query запрещены. SQLite authorizer разрешает только
  операции чтения и функций SELECT; изменения, DDL, PRAGMA и ATTACH запрещены.
  Имена выходных столбцов должны быть уникальны: для совпадений задайте AS.
- list_sheets не запускает пользовательский SELECT; его синтаксис, параметры и
  столбцы проверяются при scan/iter_chunks, чтобы перечисление не выполняло JOIN.
- База открывается через URI с mode=ro: только для чтения, без создания базы
  при неверном пути. Имена таблиц проверяются и экранируются как идентификаторы.
- Для table сканирование использует LIMIT. Для query исходный SQL не
  переписывается: курсор получает не более sample_rows строк через fetchmany,
  после чего закрывается. Это сохраняет параметры, CTE, комментарии и исходные
  имена столбцов (обёртка SELECT может автоматически переименовать дубликаты).
  COUNT(*) не выполняется, row_count остаётся None. Сортировка, группировка
  или JOIN внутри SQL могут потребовать обработки больших объёмов независимо
  от размера выборки. Время также зависит от открытия базы и блокировок.
- Импорт выполняет один SELECT и получает строки через fetchmany. Повторных
  запросов с растущим OFFSET нет. Закрытие генератора закрывает курсор и соединение.
- Без ORDER BY порядок строк между независимыми запросами не гарантируется.
  Выборка — первые полученные строки запроса, а не случайная выборка.
  Возобновление поддерживается только тем же открытым генератором.
- Длительная пауза может удерживать блокировку чтения. scan и iter_chunks
  используют отдельные соединения: если базу изменили между ними, данные могут
  отличаться. Сохранение состояния после перезапуска не реализовано.
- Метаданные описывают фактические значения выборки, а не объявленные SQL-типы.
  NULL считается пропуском. Даты, хранящиеся текстом, остаются строками.
  Порция из одних NULL может иметь тип object; при объединении итоговый dtype
  может зависеть от размера порции. Для явной схемы используйте dtype в ImportSession.
- Пустая таблица даёт один пустой DataFrame с названиями столбцов.
- Ошибки SQLite преобразуются в SourceReadError с путём, операцией, именем
  таблицы и исходной причиной. Неверные аргументы вызывают ValueError.

## Вопросы, по которым нужно было принять решение и выставить ограничения


| Вопрос | Текущее решение | Причина и ограничение |
| --- | --- | --- |
| Число строк | CSV: оценка по байтам; Parquet: точные метаданные; XLSX/SQL: None | Избегаем полного подсчёта; точность CSV обозначена отдельно |
| Метаданные | По первым N строкам | Ограниченная стоимость чтения; поздние особенности могут не попасть в выборку |
| SQL-лист | Результат SELECT, table оставлен как сокращение | JOIN нескольких таблиц всё равно возвращает один лист |
| Продолжение | pause/resume сохраняют тот же читатель | Пауза в процессе; после перезапуска продолжить нельзя |
| Итоговый результат | Один DataFrame | Требование задания; результат должен помещаться в память |
| Ошибка преобразования | Остановить импорт с подробной ошибкой | Не теряем ошибочные строки незаметно |
| Прогресс | Процент по переданным metadata; без них — строки и порции | Оценочность отмечается отдельно; при превышении процент неизвестен |

## Принятые решения и ограничения CSV

- Первая строка CSV содержит заголовки. Разделитель — один символ.
- Логический лист называется по имени файла без расширения.
- Сканирование анализирует первые `sample_rows` строк данных, без заголовка.
- row_count оценивается по формуле: ceil((байты файла − байты заголовка) /
  (байты прочитанных записей / количество прочитанных записей)). Оценка не
  меньше числа прочитанных строк. row_count_is_estimate=True обозначает оценку.
- Если выборка достигла конца файла, возвращается точное число прочитанных
  строк и row_count_is_estimate=False. Для файла только с заголовком это 0.
  None по-прежнему обозначает неизвестное число; False при None не означает точность.
- Физические строки читаются с сохранением переводов строк. csv.reader
  объединяет поля в кавычках с переносами в логические записи; байты считаются
  инкрементальным кодировщиком, с учётом BOM. Типы и пропуски определяет pandas
  по собранной выборке. Проверены UTF-8, UTF-8-SIG, CP1251, UTF-16 и UTF-32.
  Экзотические кодировки с несколькими эквивалентными байтовыми представлениями
  могут давать дополнительную погрешность. Поддерживаются несжатые CSV.
- Пустые строки в выборке учитываются в объёме байтов, но не как записи.
  Неодинаковая длина записей и распределение пустых строк снижают точность
  оценки. Прочтение первых N записей не гарантирует репрезентативность.
- Для разбора границ записей действует лимит размера поля стандартного csv.reader
  (csv.field_size_limit); превышение вызывает SourceReadError.
- Передача metadata в ImportSession включает приблизительный процент по этой
  оценке; фактически принятые строки и порции также доступны.
- Типы и пропуски относятся только к выборке. На пустой выборке типы
  неинформативны. Пропуски распознаются по стандартным правилам pandas,
  включая пустые значения и некоторые текстовые маркеры, например `NA`.
- Парсер может читать данные с буферизацией: лимит строк выборки не означает
  точный лимит прочитанных байтов. Пустые строки пропускаются по правилам pandas.
- Полностью пустой файл вызывает SourceReadError; файл только с заголовками
  допустим и даёт пустую таблицу.
- При прямом iter_chunks типы каждой порции определяются pandas отдельно.
  Явная схема и преобразования доступны через ImportSession.
- Повторный вызов iter_chunks начинает чтение сначала. Продолжить можно тот же
  генератор, пока он открыт. Продолжение после перезапуска пока не реализовано.
- Итоговый DataFrame должен помещаться в память.
- Ошибки чтения оборачиваются в SourceReadError с сохранением исходной причины.
  Некорректные аргументы вызывают ValueError.
